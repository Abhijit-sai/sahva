# ADR-0007 · Direction-specific translation for evaluation

Proposed for the translation lab. Production uses the accepted Sarvam group pipeline. Experimental selection belongs to the listener. In a Telugu/English meeting the speaking preference describes that person's microphone; the incoming translated pair uses each remote speaker's language and the listener's listening preference. Keep matching-language original playback. Preserve the selected languages on engine changes. Show only pairs supported by the adapter and proved with authenticated audio in this environment. Provider documentation, credential presence and runtime verification are distinct.

Fork an independent speaker's consent-scoped PCM at the existing bridge. Group by room epoch, active source track, target and engine. Keep the original track and Sarvam timeline/report intact. Route experimental output only to the requesting members. Stop on withdrawal, track teardown or listener changes. Surface failure and let the listener explicitly return to Standard. Provider-specific end signals, interim transcripts, voice controls and sample rates belong in each adapter. Live output is experimental evidence; canonical records continue to identify the Sarvam path. Ordinary rooms retain their current interface.

Benchmark files are consented, bounded, replayed at source pace, and identified by decoded PCM hash. Keep captured pauses and final partial packets. Use a duration-preserving sample-rate conversion where required by an API. Keep server arrival, browser playback and reviewer judgments distinct. Rank by meaning, critical terms, delay, reliability, naturalness and cost per direction. Negation, dates, prices and invented commitments require fluent review before promotion. No automatic provider promotion.
