# Isolated IndicTrans2 worker

Build for Linux x86-64 on the isolated host. The CUDA wheel set is in requirements.lock. Confirm the NVIDIA driver supports its CUDA runtime. The host must expose the NVIDIA Container Toolkit. Use the services/indictrans2 folder as the Docker build context.

For the Oregon CPU trial use the same pinned image and cache, omit `--gpus device=0`, and pass `-e SAHVA_MT_DEVICE=cpu -e OMP_NUM_THREADS=8`. This uses FP32 and reports CPU thread count on each receipt. The default remains CUDA FP16. The two startup warmups use fictional short text in opposite directions. Measure cold startup separately from subsequent requests. For the paired quality test, use the existing `scripts/s2st/mt-compare.ts` harness with the reviewed manifest. Keep raw recordings on the operator machine.

To exercise the trial before human review, run `node --env-file-if-exists=.env.local --experimental-strip-types scripts/s2st/mt-compare.ts --fictional paired 3` at the repository root with the private tunnel active. This uses only the first five bilingual rows of the canonical recording sheet. Receipts label both directions as fictional scripts, preserve a text digest, and have no audio hash. A reviewed recording manifest still requires the original consent and verification fields.

1. Review the two Hub gates and pinned custom tokenizer/model code. After gaining access, stage both snapshots in a private HF cache. With huggingface_hub installed, use `huggingface-cli download MODEL --revision SHA --exclude "*.bin" --cache-dir /private/hf/hub` for each ID and SHA in model.py. The worker uses safetensors and offline loading. Retain the cache directory hierarchy.
2. Build `docker build --platform linux/amd64 -t sahva-indictrans2:trial .` and record the built image digest. The image excludes weights and tokens.
3. Store a random token of at least 32 ASCII characters in a private operator env-file as SAHVA_MT_TOKEN. Mount the approved cache read-only and readable by UID 65532. Set a separate host expiry with the approved budget.
4. Run `docker run -d --name sahva-mt --restart on-failure:3 --gpus device=0 --read-only --tmpfs /tmp:rw,nosuid,size=256m --cap-drop ALL --security-opt no-new-privileges -p 127.0.0.1:8080:8080 --mount type=bind,source=/private/hf,target=/models,readonly --env-file /private/mt.env sahva-indictrans2:trial`. Access from the lab through an authenticated private tunnel. Only loopback should be published. Check the authenticated /ready and /v1/capabilities responses. Startup loads both checkpoints and requires nonempty inference in each direction. Start-up failure prevents serving. Record cold-start wall time externally.
5. The adapter sends UTF-8 JSON to /v1/mt/translate. One accepted request occupies the GPU. Excess concurrent requests return BUSY, and a rolling per-worker limit allows 60 accepted calls per minute. A 15-second inference deadline returns an error. A hung job causes process restart after a further 30 seconds. Record failed requests, external GPU utilization and peak VRAM as well as model-reported allocated bytes.
6. On the host, stop the named trial container. Stop the experimental EC2 instance immediately and verify its stopped state. Retain the encrypted EBS checkpoint cache for the next authorized start. Record session uptime and residual storage charges. The AWS runbook covers the start/stop procedure and deadline.

The lock resolves the proposed dependency set. Runtime compatibility with the gated snapshots requires real CUDA qualification. Model metadata and quota observations are in the provider document and AWS runbook.
